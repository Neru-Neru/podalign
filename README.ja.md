# podalign

[![CI](https://github.com/Neru-Neru/podalign/actions/workflows/ci.yml/badge.svg)](https://github.com/Neru-Neru/podalign/actions/workflows/ci.yml)
[![License: AGPL-3.0](https://img.shields.io/badge/license-AGPL--3.0-blue.svg)](LICENSE)

**別々に録音したポッドキャストの音声を、自動でそろえて配信できる形に仕上げるツールです。**
自分のパソコン(またはサーバー)で動かし、ブラウザから操作します。

[English README](README.md)

> **開発状況:** 公開したばかりです。テスト用の音源での確認は済んでいますが、
> 実際の収録素材での検証はこれからです。うまくいかない点があればぜひ報告してください。

## なにをしてくれる?

リモート収録(通話しながら各自が手元のマシンで録音するスタイル)では、あとで録音を集めて重ねると:

- 録音の開始タイミングが人によってバラバラ
- さらに、機材ごとの内部時計のわずかな差で、**時間がたつほど音がずれていく**(1時間で最大 0.2 秒ほど)

頭出しを手作業でそろえても、この「だんだんずれていく」問題は直りません。

podalign は通話の録音を手がかりに、各自の録音について**開始位置のずれ**と**ずれていく速さ**の
両方を自動で測って補正します。補正後のずれが 1000 分の 1 秒以内に収まっているかまで
自動でチェックし、収まっていなければ画面に警告を出します。

そのあと、ポッドキャスト編集の定番の仕上げも自動で行います:

- ノイズや電源ハムの除去
- 声の大きさをそろえる
- BGM とジングルの合成(会話中は BGM の音量が自動で下がります)
- 配信サービスの標準的な音量(-16 LUFS)への調整

Sync のあとには手動 Trim 工程があります。話者2〜3人と全体音声(リファレンス)の3〜4本を
同じ時間軸で確認し、ドラッグまたは左右のハンドルで収録前後を範囲選択して切り出します。
実行前に全体音声や各話者を聴きながら範囲を調整でき、選択範囲だけの試聴もできます。
無音の自動検出や間の自動詰めは行いません。

各工程はブラウザの画面で**処理前と処理後を同じ位置から聴き比べて、OK を出してから次へ進む**
流れです。勝手に音が変わったまま完成してしまう心配はありません。
最後に WAV / MP3 / AAC の完成ファイルを書き出します。

## 用意するもの

音声ファイル 5〜6 個です:

| ファイル | 説明 |
|---|---|
| 各話者の録音 × 2〜3 | それぞれが手元で録音した音声(最低2人、最大3人に対応) |
| 通話の録音 × 1 | Zoom などの通話側の録音。**ずれの測定にだけ使い、完成品には入りません** |
| ジングル × 1 | オープニングなどに入れる短い音 |
| BGM × 1 | ループ再生される背景音楽 |

## 使いはじめる

### Docker で動かす(おすすめ)

[Docker](https://docs.docker.com/get-docker/)(Docker Compose を含む) と `make` が入っていれば、リポジトリのルートで次の 1 コマンドでビルドと起動ができます:

```bash
make start
```

ブラウザで http://localhost:8000 を開けば準備完了です。
必要なソフト(特別なビルドの ffmpeg)はすべて同梱されているので、他に準備はいりません。
停止は `Ctrl+C`。音声やプロジェクトは `data/` に保存され、再起動後も残ります。

`make` だけでも起動できます。`make stop` で停止とコンテナの片付けができます。
音声・プロジェクト・完成ファイルもすべて削除する場合は、次のコマンドを実行してください。
**削除は元に戻せないため、必要な完成ファイルは先にダウンロードしてください。**

```bash
make clean-data
```

### Docker を使わない場合

必要なもの:

- **ffmpeg**(librubberband 対応ビルド。Ubuntu の `apt install ffmpeg` や
  Mac の Homebrew で入るものはそのまま使えます)
- **Python 3.10 以上**と [`uv`](https://docs.astral.sh/uv/)
- **Node 22**(初回に画面をビルドするときだけ使います)

```bash
# 初回のみ: 依存の導入と画面のビルド
uv sync
cd web && npm install && npm run build && cd ..

# 起動
uv run uvicorn app.main:app --host 0.0.0.0 --port 8000
```

ブラウザで http://localhost:8000 を開きます。
お使いの ffmpeg が対応ビルドでない場合は、起動時にその旨のエラーで止まるので分かります。

## ⚠️ 必ず「自分だけが使えるネットワーク」で

podalign には**ログイン機能がありません**。自分のパソコン・自宅の LAN・
VPN(Tailscale など)の内側だけで使ってください。**インターネットに直接公開しないでください。**
アドレスに到達できる人は誰でも、音声のアップロードやプロジェクトの削除ができてしまいます。

## よくある質問

**Q. 編集の途中データでディスクがいっぱいになりませんか?**
途中データは 1 エピソードあたり約 3.5 GB を目安に作られます。画面から削除でき、
削除しても必要になれば自動で作り直されるので、安心して消せます。

**Q. 一度 OK を出した工程を、あとからやり直せますか?**
はい。設定を変えると、影響を受ける工程だけが自動でやり直しになります。
影響のない工程は再計算されません。
再実行する工程の古い生成物は開始前に削除し、失敗時も途中の生成物を削除します。
原素材・他の工程の生成物・Exportの完成ファイルは、この削除の対象にはなりません。

**Q. 最後にBGMだけ残る時間を変えられますか?**
Mixの「話者終了後にBGMを残す時間 (秒)」で指定できます。0秒なら話者と同時に終了、
3秒なら話者終了後に3秒残ります。BGMの開始位置はそのまま、最後の最大3秒でフェードアウトします。
新規プロジェクトは3秒が既定値です。既存プロジェクトは未指定の間、従来の長さを維持します。
変更後はMixを再実行・承認し、Master以降も再実行してください。

**Q. 2 人番組や 4 人番組でも使えますか?**
2人・3人構成に対応しています。話者A/B/Cのうち最低2人分をアップロードしてください。4人以上には未対応です。

## しくみを詳しく知りたい方へ

<details>
<summary>同期アルゴリズムの概要(技術者向け)</summary>

1. **粗探索** — 50 Hz RMS エンベロープ同士を相互相関 → ±20 ms 精度
2. **区間別微調整** — 収録を約 10 区間に分け、8 kHz 波形を GCC-PHAT
   (両端テーパー+放物線補間)で相関 → サブサンプル精度の「時間 vs ずれ」系列
3. **ロバストフィット** — 話者が無音の区間を RMS と相関信頼度で除外し、
   Theil–Sen 初期値+重み付き最小二乗で直線フィット → 切片=オフセット、傾き=ドリフト率
4. **補正** — オフセットはサンプル単位の `atrim`/`adelay`、ドリフトは |s|≥5 ppm のとき
   `rubberband=tempo=(1+s)`(atempo は ppm 級で無効なことを実測済み)
5. **検証** — 補正後に再相関し、残差 ±1 ms 以内を assert

</details>

<details>
<summary>各工程の処理内容(技術者向け)</summary>

音の加工はすべて ffmpeg サブプロセスが行い、Python(numpy)は解析とパラメータ決定のみを
担います。各ステージは「上流成果物+パラメータ → 成果物」の決定論的な純関数として動きます。

| Stage | 処理 |
|---|---|
| 0 Ingest | ffprobe 検証 → 48 kHz/FLAC 24 bit へ統一 → クリップ率/DC/無音率の QC |
| 1 Sync | オフセット+クロックドリフトの推定・補正 |
| 2 Trim | 3〜4本の波形から手動で共通範囲を選択し、48 kHzサンプル単位で切り出し |
| 3 Cleanup | ハイパス 80 Hz → ハム自動ノッチ(50/60 Hz 自動判別) → declick/declip → `afftdn` NR(≤12 dB) → ディエッサー → 控えめなゲート → -20 LUFS へ純線形ゲイン |
| 4 Dynamics | 2 段コンプ(グルー 2.5:1 → ピーク 6:1)+控えめ EQ |
| 5 Mix | ジングル・話者バス・BGMを絶対時刻のタイムラインに配置して `amix`。既定ではジングルを0秒、話者をジングル終了時、BGMを話者開始10秒後に2秒でフェードイン（BGMはシームレスループ＋サイドチェインダッキング） |
| 6 Master | 2 パス linear `loudnorm` で -16 LUFS / -1.5 dBTP → セーフティリミッター -1.0 dB |
| 7 Export | WAV 24 bit / MP3 192k CBR / AAC 128k + QC レポート |

</details>
