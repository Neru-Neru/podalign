# 音声処理の実装・比較結果

既存のFFmpegによる加工、NumPyによる解析、ステージ順、Trim、同じ位置でのA/B試聴、段階承認を維持して改善した。実行時依存の追加はない。以下は合成音声による実測であり、実録音の聴感品質が向上したと断定するものではない。

## 実装内容

| 項目 | 実装と安全策 |
| --- | --- |
| SNR・VADによるNR判定 | 20msフレームのエネルギーとスペクトル平坦度を解析。発話・非発話が各0.5秒未満、または分離が不明瞭なら自動NRを省略。`auto`は推定SNRが30dB以上なら無処理、25〜30dBは最大6dB、それ未満は最大9dB。上限設定も適用する |
| 非定常ノイズ | VAD非発話区間と、VADから独立した平坦なスペクトルの区間のエネルギー変動を併用。複数の急な広帯域イベントも検査。自動・弱・中では変動ノイズまたは推定SNR10dB未満を最大3dBに制限 |
| NR前後の劣化検査 | HPF等の後、NR直前で発話マスクを固定。NR直後だけを比較し、発話帯域減衰3dB超または推定SNR改善量−0.5dB未満なら、元のNR直前音声から最大3dB、無処理へ順に再試行。最大3回。従来モードにも検査と遅延補償を適用 |
| 300〜3400Hz保護 | FFmpegの相補的FFTマスクで、同帯域は原音を50%混合。200〜300Hz、3400〜3800Hzを滑らかに接続。NR経路と原音経路の遅延を合わせる。保護なしとの比較も可能 |
| HPF設定 | 20〜200Hzで設定可能。40/60/80Hzを比較した。既定80Hzを維持 |
| マイクかぶり | 同期・Trim後、整音前のトラックを解析。最大120個の時間分散窓、±10msの遅延付き正規化相関でかぶり・重複音声・極性反転候補を警告。自動除去や極性変更はしない |
| 個別増幅上限 | 共通上限12dBと話者別上書き。−60LUFS以下は増幅停止。True Peak上限−1dBTPと0.1dBの測定余裕を守る線形ゲイン。必要な減衰は制限しない |
| VAD同期アンカー | 時間帯ごとに発話量が多い解析窓を選択。無音ゾーンは除外するが、全体で3アンカー未満なら停止。従来の等間隔方式も選択可能 |
| RANSAC | 64アンカー以下の全ペアを決定的に評価。1秒以上の時間間隔、1msの合意許容幅、傾きの妥当性を確認し、合意数・時間的広がり・信頼度で選択。合意不足を全点inlier扱いにするフォールバックはない |
| Polyphase | FFmpegのswresampleを利用。仮想レートと分母100万以下の有理比でppm補正を表し、48kHzの整数レート変更による約20.8ppm刻みの制約を回避。Rubber Bandと選択可能。SciPyは追加しない |
| 低同期信頼度 | アンカーの時間的広がり、合意率、残差、矛盾する高信頼区間、補正後の再検証を確認。低信頼度ではAPIとGUIの両方で承認を停止。手動オフセットを設定しても再検証する。危険を理解した明示設定で再実行した場合だけ上書き承認を許可し、レポートに記録する |

NRのSNRは8kHz解析音声に対するVAD推定値であり、合成素材に与えた48kHz全帯域の既知SNRとは一致しない。無声子音・囁き・音楽・突発音を完全に判別するVADではない。解析根拠、推定SNR、変動性、試行強度、減衰、制限理由をレポートで確認できる。

従来のNR強度・ノイズフロア選択を既定に残し、`auto/off/light/medium`を既存Cleanup画面で選択できる。話者別設定も可能。従来モードは帯域保護なしだが、劣化検査と遅延補償は共通化した。HPF、ゲート、ディエッサー、Dynamicsの役割は維持する。NR無効でもゲート等は動作する。

同期の既定も等間隔・Theil–Sen・Rubber Bandを維持した。比較で優位な条件と不利な条件があり、限定的な合成結果だけで一律に置き換えない。既存プロジェクトの保存設定・承認済み成果物は移行しない。再実行時に安全策を適用する。

## 遅延と資源

インパルスによって、インストール済みFFmpegのNRとFFTフィルタの遅延を校正する。この環境では48kHzでNRが1200サンプル、FFTが768サンプルだった。校正値で並列経路を揃え、末尾をパディングしてから切り出し、音声長と末尾イベントを保持する。NR無効・従来・自動などを話者別に混在させても、NR由来の遅延差を残さない。校正不能なら処理を停止する。

加工前のピークを失わないよう、ゲイン前はfloat32 WAVを使い、大容量時はRF64を使う。NR前・NR後・ゲイン前のファイルは、不要になった時点で順に削除する。最大で話者ごとに2本のfloat中間音声が並存し、48kHzモノ1時間なら約1.38GB、2並列なら約2.76GBに相当する。FLAC成果物と余裕を含めた空き容量を実行前に確認する。劣化検査・再試行・追加ファイル入出力は処理時間を増やす。NR単体の別seed群8秒素材では、無処理平均0.411秒、自動平均1.433秒だったが、この測定は他テストとの同時実行を含み、長時間音声へ単純に外挿できない。解析FFTの作業行列は2048フレームずつ処理する。ただし8kHz解析音声そのものはメモリ上に保持する。

## 比較条件と記録

- FFmpeg 7.1.5、48kHzの合成発話・既知ノイズ。NR・HPFは8秒、同期は120秒。
- 開発用seedは1/7/29、別の検証用seedは101/107/129。後者を見て閾値を再調整していない。
- 各群でNR144条件、HPF9条件、同期48条件、外れ値回帰24条件、8kHzドリフト補正8条件、かぶり3条件。別途48kHz補正8条件と、旧Cleanup全体対新Cleanup全体の6素材A/B。
- [開発群](measurements/development.json)、[別seed群](measurements/holdout.json)、[48kHz補正](measurements/resampling-48k.json)、[全体A/B](measurements/cleanup-ab.json)に数値を保存した。音声ファイルはベンチマークで再生成できる。

NR単体比較の固定12dB経路は、同じ推定ノイズフロア、共通の遅延補償を用いて、処理強度と帯域保護の効果を切り分けた対照である。旧Cleanup全体の完全な再現比較は、別の`audio_ab`で旧コミット`4551fe76c243bc0260713ce1d0f5185d75c90d17`の順序・中間FLAC・ゲイン計算を固定して行う。

### NR単体

別seed群の固定発話マスクに対するSI-SDR平均。無処理と自動NRを、同じ既知のクリーン音声と比較した。

| 素材 | 無処理 | 固定12dB・保護なし | 自動・保護あり | 自動の選択強度 |
| --- | ---: | ---: | ---: | ---: |
| 入力SNR 0dB | 0.001dB | 0.125dB | 0.113dB | 9dB |
| 入力SNR 10dB | 9.997dB | 10.305dB | 10.283dB | 9dB |
| 入力SNR 20dB | 19.995dB | 20.946dB | 20.844dB | 6dB |
| 入力SNR 30dB | 29.995dB | 31.061dB | 29.995dB | 0dB |
| 入力SNR 40dB | 39.994dB | 40.365dB | 39.994dB | 0dB |
| 変動ノイズ | 13.569dB | 13.886dB | 13.803dB | 3dB |
| 打鍵音様ノイズ | 18.524dB | 19.259dB | 19.060dB | 3dB |

静かな素材では両群とも自動NRを省略し、NR部分は原音と一致した。変動・打鍵音では両群の全6素材で強度を3dBに制限した。保護によって低SNR素材の音声帯域減衰が小さくなる条件はあるが、FFT窓の微小な影響もあり、全条件で小さくなるわけではない。専用ストレステストでは約0.243dBから0.137dBに減少した。

自動NRのSI-SDRが固定12dBを上回ったとは結論しない。目的は不要な加工・強すぎる加工を避けて戻せること。SI-SDRや帯域エネルギーだけで自然さ、子音の保持、聴きやすさを保証できない。実録音の音量を揃えた聴取比較は未実施。

### HPF

開発群平均。低い声と30Hzの振動音を含む同じ素材で比較した。

| 周波数 | 20〜40Hzエネルギー変化 | 90〜150Hz基音帯域変化 |
| --- | ---: | ---: |
| 40Hz | −6.19dB | −0.077dB |
| 60Hz | −12.31dB | −0.372dB |
| 80Hz | −17.13dB | −1.080dB |

40Hzは声の低域を残しやすく、80Hzは振動音を減らしやすい。目的が異なるため既定を40Hzへ一律変更しない。

### 同期・RANSAC

| 条件 | 等間隔・Theil–Sen | 等間隔・RANSAC | VAD・Theil–Sen | VAD・RANSAC |
| --- | ---: | ---: | ---: | ---: |
| 通常・開発群 | 3/3 | 3/3 | 3/3 | 3/3 |
| 長時間無音・開発群 | 1/3 | 1/3 | 2/3 | 2/3 |
| 通常・別seed群 | 3/3 | 3/3 | 3/3 | 3/3 |
| 長時間無音・別seed群 | 0/3 | 0/3 | 1/3 | 1/3 |

無関係音声・10msの途中ジャンプは、両群の全方式で自動受理しなかった。VADは長時間無音で改善する条件があるが、なお拒否する素材がある。成功数を増やすために安全閾値を緩めていない。

独立した16アンカーの外れ値回帰では、開発群の外れ値0/25%は両方式で復元できた。50/約70%ではTheil–Senに約9〜141ms、約95〜214ppmの誤差が生じるケースがあり、RANSACは既知値を復元した。ただし合意率・矛盾率の検査は別に行うため、少数合意で正しい直線を推定できても自動承認は保証しない。

### Rubber BandとPolyphase

48kHz・120秒、−100/−12/+12/+100ppmの4条件を比較。検証は8kHzで独立に再推定した。

| 方式 | 最大区間残差 | 最大残留ドリフト | 処理時間平均 | 子プロセスRSSの最大サンプル値 |
| --- | ---: | ---: | ---: | ---: |
| Rubber Band | 0.0246ms | 0.0206ppm | 1.354秒 | 37632KiB |
| Polyphase | 0.0056ms | 0.0085ppm | 0.155秒 | 35560KiB |

全条件で5760000サンプルを保持した。8kHz比較でも両方式が1ms/1ppm以内だった。Polyphaseは100ppmで約±0.173centの音程変化を測定した。Rubber Bandの単音測定でも最大約0.171centの微小差が出たため、この短い単音測定で完全な音程保持を保証しない。5/12/20kHz成分の48kHz回帰テストでは両方式ともエネルギー差0.5dB以内。48kHzの時間・メモリは他のベンチマーク終了後に単独で測定したこの環境の値であり、RSSは5ms間隔の近似測定、帯域・チャンネル数・長さが異なる録音への性能保証ではない。

### かぶりとゲイン安全策

4ms遅延・極性反転・振幅0.3倍のかぶりは、開発群・別seed群とも全3/3で検出。独立した音声対照は全3/3で警告なし。強い同時発話・残響・音楽などの実録音一般への検出率は未確定。

旧Cleanup全体とのA/Bでは、瞬間ピーク素材が+2.1dBTP・24bit飽和41サンプルから、−1.1dBTP・飽和0サンプルへ変化した。通常素材は−20.0LUFSを維持。極小素材は旧+47.1dB増幅に対し、新版は増幅停止となり−66.7LUFSに留まった。音量目標より安全を優先した結果であり、素材レベルの見直しが必要な場合がある。

## 再現手順

```sh
uv sync
uv run python -m benchmarks.audio_ab --output docs/private/cleanup-ab
uv run python -m benchmarks.pipeline_comparison --output docs/private/development --seeds 1 7 29
uv run python -m benchmarks.pipeline_comparison --output docs/private/holdout --seeds 101 107 129
uv run python -m benchmarks.resampling_48k --output docs/private/resampling-48k
uv run pytest -q
uv run ruff check app tests benchmarks
uv run mypy app tests/audio_fixtures.py benchmarks
cd web
npm ci
npm run build
CHROME_BIN=/path/to/chrome npm run test:trim
```

この管理環境ではChromiumの直接`--dump-dom`実行が空ページでも終了しなかったため、GUI回帰は同じテストHTMLをループバックHTTP配信し、インストール済みPlaywrightの起動経路で実行した。Playwrightはプロジェクトの依存に追加していない。CIはChromeを直接実行する。テストにはNR・話者別設定・手動オフセット0・ポーリング保持・低信頼度の承認停止と、既存Trim/Mix操作を含む。
